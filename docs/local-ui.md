# 本机浏览器界面

在仓库 PowerShell 中启动。需要现有 Python/uv 环境、已启动的 Docker Desktop Linux 引擎、已验证镜像及当前终端中的模型凭据。不要将密钥写入页面、截图或版本库。

```powershell
Set-Location 'D:\ai coding\metricguard'
$env:PYTHONUTF8='1'
uv sync --locked
docker build -t metricguard-check experiments/t02
$env:METRICGUARD_TEST_IMAGE=(docker image inspect metricguard-check --format '{{.Id}}')
uv run python -m metricguard.web_start --demo
```

默认地址为 http://127.0.0.1:8765 ，以启动终端实际显示的地址为准。不支持其他设备访问或使用 localhost 别名。端口占用可加 `--port 8766`。模型服务默认使用既有 DeepSeek 兼容端点；管理员可在启动命令追加 `--base-url https://api.deepseek.com/anthropic`，页面不接受此设置。命令先检查配置及实际隔离查询环境，不会调用模型生成报告；准备完成后显示地址。

## 整体复验入口

完成上述环境配置后，可用一条命令启动包含普通查询和分系统留存示例的独立验收界面：

```powershell
uv run python -m experiments.u6_manual
```

该入口调用同一个正式 Web 启动器，数据和任务保存在 `artifacts/u6-manual/`；同一目录重启保留原任务。默认端口 8765，冲突时加 `--port 8766`。简短步骤、停止和恢复操作见 [人工复验清单](validation/u6-manual-checklist.md)，各项自动、真实模型及人工结果见 [U6 验证记录](validation/u6-report.md)。用户已于 2026-10-19 确认核心流程人工验收通过，记录与自动验证分开保存。

运行透明度与断连恢复这一轮（#36）的逐项覆盖见 [U13 验收记录](validation/u13-report.md)，用户复验见 [U13 简短清单](validation/u13-manual-checklist.md)。本轮人工体验仍待确认；此前 U6 的人工通过不替代本轮确认。

## 做一次查询

1. 打开地址，点击“填入开发示例”。问题和 2026-01-08 至 2026-01-15 日期均可见、可修改，结束日不包含。
2. 点击“开始分析”，页面显示状态和本次运行历时。示例新增用户数应为 1680 人，实际值同时应核对已发布证据。
3. 可复制任务链接。关闭或刷新页面不取消后台任务，重新打开原链接可查看结果；不会再次提交执行。
4. 需要新问题时点击“新建问题”，编辑后再次提交。其他任务仍在执行时会明确拒绝，不进入后台队列。

需要使用已配置的其他兼容快照时，省略 --demo，使用 `--snapshot 名称=完整路径`，可以重复提供。只接受既有业务结构的 DuckDB 快照，不支持上传或任意表结构。默认界面工作目录为 artifacts/local-ui/state；可用 --state-dir 指定独立目录。不要让 CLI 和网页同时持有同一个目录。

浏览器暂时收不到提交结果时，“重试相同提交”沿用原操作标识，避免重复执行；修改内容应先点“新建问题”。服务重启后同一操作仍去重；未确认完成的异常操作不会自动重放。

## 查看执行进展

任务区分别展示执行状态、当前动作、最近可靠进展时间和连接状态。动作随真实执行变化，模型请求与查询可能交替多次；只有实际整理报告时才显示报告阶段。没有可靠动作记录时显示粗粒度状态，旧任务缺少进展时间时显示“未记录”。刷新、重新打开和服务重启不会把读取时间记为分析进展。

运行任务连续 60 秒没有新的进展记录时，页面温和提醒当前动作可能仍在进行，不据此判定失败或自动重试。等待澄清时不出现此提醒。读取失败时标注最后已知信息，恢复读取后再以服务记录为准。“本次运行历时”仍是本次执行时间，不代表累计预算、完成比例或预计剩余时间。

## 回答澄清

任务进入“等待澄清”时，结果区显示已知条件、当前问题、建议回答和自由输入框。选择建议只会填入答案；点击“提交回答”才继续。可以直接输入指标、日期或其他明确回答，不需要复制内部问题 ID 或版本。

- 日期冲突时选择本次真正需要的窗口；比较基期、缩小可用范围也需要逐项确认。选择“保留原范围”会得到证据不足说明，不会偷偷缩小查询日期。
- 合法回答在同一个任务中继续，保留时间锚点、已确认条件和原有预算。等待时不占执行位置，可另建问题；可从历史列表或原任务链接返回。
- 页面刷新会读取最新待答问题。旧标签页提交过期回答会被拒绝，点击“刷新待答问题”即可获取当前问题。
- 其他任务正在执行时，回答不会先被消费；收到忙碌提示后稍后再次提交。
- 回答响应丢失时可“重试相同回答”，沿用原操作标识；也可刷新读取实际状态。不会因此重复运行。服务在回答期间意外退出时，未知操作不会自动重放。
- 执行或检查点异常会显示失败/中断并保留记录；可通过“创建关联重跑”启动新任务，保留原记录。
- “本次运行历时”按本次创建或回答后执行阶段显示，等待不累计为运行时间；它不替代服务的累计活动预算。

## 历史任务与恢复

左侧历史列表按创建顺序倒序显示当前 Web 工作目录的任务。点击问题可查看状态或结果；正在运行的任务只读取状态，不会重新执行。列表可手动刷新，读取失败会提示旧列表可能不是最新状态。

手动验证等待任务恢复：

1. 用“用户表现怎么样？”创建任务，保持等待澄清；另建一个简单查询并等待结束。
2. 在启动终端按 Ctrl+C 正常停止，再以相同启动命令和相同 `--state-dir` 启动。
3. 从历史列表打开等待任务，核对已知条件并回答。任务 ID 应不变；原时间锚点、已确认信息和预算继续沿用。
4. 打开先前已结束的任务，结果应仍可读；刷新或重新打开不应触发新分析。

新工作目录显示空列表；不会导入旧 CLI 或历史验收目录。无效任务链接会明确提示，可从列表选择任务或新建问题。自动化测试已覆盖受控跨日恢复，尚未登记人工跨日验收。

## 失败、中断与重跑

服务意外停止后，重新以同一工作目录启动，从历史列表打开任务查看“已中断”说明。未知模型调用不会自动重放；刷新、查看历史均不会恢复执行。模型超时或失败也会给出说明并保留已有记录和证据；预算保护导致的“已结束”不等于分析成功，请同时阅读恢复说明及报告限制。

- 点击“创建关联重跑”创建新 ID，沿用原服务的重跑规则、已确认条件与明确日期，保留原任务和证据。新任务提供“查看原任务”链接；这是重新执行，不是断点续跑。
- 重跑同样占用唯一执行位置；忙碌时明确拒绝。响应丢失时，可点击“重试关联重跑”，刷新后仍沿用同一操作，不重复创建任务。
- 点击“复制并修改”将旧问题、快照、明确日期和比较基期填入可编辑表单。修改并点击“开始分析”才创建独立任务；不会继承旧结论、证据或澄清答案。
- 若原快照已不再配置或不可读取，重跑会给出创建失败说明。可复制修改后选择当前可用快照；新任务仍需正常确认分析条件。

## 状态更新与标签页草稿

可见页面上的运行任务约每 1 秒读取一次，等待澄清约每 5 秒读取一次。同一问题的更新保留正在输入的回答及焦点。后台暂停周期读取，返回页面立即核对一次，不补发错过的轮询；取消页面读取不会取消后台分析。

新问题的文字、快照和未填完整的日期，以及绑定任务/问题版本的回答草稿，保存在本标签页。刷新后可以继续编辑；不自动跨标签页同步输入，也不保证关闭标签页、换浏览器或换设备后恢复。

另一标签页已回答或问题版本变化时，本页旧回答保留在“旧回答草稿”区供选中复制，新问题不会自动带入旧答案。成功提交清除对应草稿。响应丢失时原提交内容与操作标识继续保留；若回答问题已变化，可先手动“重试原回答”确认原操作，编辑的新草稿不会替换原提交，不自动重放。

已结束或中断任务在报告读取完成后停止周期读取。报告、历史的局部读取失败各自进行有限自动恢复，保留已显示内容并提示可能过期或尚未读到；不会单独把全页标为断连。某一区域恢复只清除自身提示，其他正常区域及任务操作仍可使用；主任务或服务状态也无法确认时仍暂停提交。

两个区域分别遵循单次 10 秒等待、约 1/2/4/8/10 秒退避及两分钟总期限，包含后续请求等待和后台时间。明确拒绝或不存在时停止自动重试。可用“刷新报告”或“刷新列表”手动恢复，连续点击不并行发起重复读取。连接恢复后同步历史；各读取共用会话更新，均不触发新分析。相同问题在不同标签页提交仍是不同操作，不按问题文字做全局去重。

## 短暂断连与服务重启

任务状态单次读取最多等待 10 秒。失败或超时后保留已显示内容并标记“可能过期”，按约 1、2、4、8 秒，之后每 10 秒只读重连。从首次异常起最多自动尝试两分钟，包括请求等待和后台停留；后台暂停读取，返回页面不会重置期限。超限后停止自动尝试，可点击“立即重连”，连续点击不会并行发起多个流程。

连接或原任务状态尚未确认时，新建、回答、关联重跑的提交暂停，草稿仍可编辑、复制。恢复后根据实际任务和未知提交状态开放操作；原操作标识及内容保留，不自动重放写请求，也不恢复执行或新增模型、分析工具调用。未知提交与断连期间后来编辑的草稿分开保存；确认原提交时只清理相同内容，后来编辑的不同内容仍保留。

同地址、同工作目录重启服务后，页面遇到明确的会话失效会重新读取同源配置并核对原任务；每次读取最多更新一次会话，仍受上述超时限制。等待和结束任务按持久记录显示，已中断任务保持中断。普通访问拒绝和任务不存在会显示具体提示并停止自动重试。页面不会寻找新地址或其他目录，网络错误本身不能证明地址或目录发生变化。

## 查看分析预算占用

任务默认显示模型和工具已计入预算次数及各自上限，包含失败及已预留调用，不能当作成功调用次数。

展开“预算详情”可查看 Token 预算占用、已知用量、保留预留量，以及尚待确认和用量未知的调用数。未知不等于零；Token 占用可能包含预留，不是实际消耗或费用。模型次数、工具次数或 Token 占用达到各自上限的 80% 时，页面分别提示对应限制，这不是任务完成进度。

累计时间预算只显示服务已确认的记账值（秒数显示至三位小数），与本次运行历时不同，页面不会自行累加或通过查看触发记账。服务重启后按原有恢复规则确认的时间也沿用该值。

预算停止以服务记录为准：剩余额度需留给报告、下一次调用所需额度不足、累计时间不足或模型用量未知，都可能在比例未满时停止。普通失败和正常结束不会因预算比例自动变成预算停止。刷新、打开历史任务和展开详情均不消费或重置预算。

## 阅读报告与核查引用

默认展示已有结论、关键比较、日期范围及必要限制。查询事实、描述性候选、证据不足和未形成支持充分的异常候选分别标示；“已结束”只表示执行状态，不代表已证明原因。

1. 点击结论或比较中的 A 编号，页面自动展开完整事实表并聚焦相应事实。
2. 点击该事实下的证据位置，自动展开原始证据并聚焦具体单元格。行号从 0 开始；表格保留原始值，展示百分比可能取整。
3. 支持依据、反对证据与对照、完整推断可按需展开。未排除因素、因果限制和范围不足说明保持默认可见。
4. 原始证据区包含查询参数、字段类型、快照、截断状态等；执行记录区保留发布版本、范围授权和 Trace。完整文本报告仍可展开。

浏览证据只读，不重新执行分析或生成模型摘要。无报告、已知失败或读取失败会明确提示。报告接口只允许当前 Web 任务，不能用于浏览任意本机文件。

## 当前阶段边界

- 已提供新建、状态、分层报告、历史列表、任务链接与连续澄清回答。提供关联重跑与复制修改。
- 简单查询无需比较基期；诊断若缺少条件可能进入等待。不要把“等待澄清”当成失败或后台还在运行。
- 模型故障与查询失败会保留服务任务记录，页面显示安全的失败说明；超时/失败说明中提供关联重跑入口。
- 页面历时不是预算活动计时；服务的真实预算规则保持不变。
- 按 Ctrl+C 停止服务会等待已接受执行结束；强制结束进程可能中断任务，不会从任意位置自动继续。
- 凭据只由服务端从 ANTHROPIC_AUTH_TOKEN 读取。第一版不提供账号、网络访问、密钥设置或依赖自动安装。

## 自动复验

仓库统一检查入口为 `uv run python -m tools.check`，依次执行验收证据、类型检查和完整测试；CI 使用同一入口。环境准备和单阶段命令见 [检查说明](agents/checks.md)。

开发测试依赖已写入依赖锁文件。浏览器测试在 Windows 默认使用已安装的 Microsoft Edge；其他安装可通过 METRICGUARD_BROWSER_CHANNEL 指定受支持的浏览器通道。浏览器缺失会使必要测试失败，不会静默跳过。

```powershell
uv run pytest tests/test_u1_web.py tests/test_u1_browser.py tests/test_u2_web.py tests/test_u2_browser.py tests/test_u3_history.py tests/test_u3_browser.py tests/test_u4_web.py tests/test_u4_browser.py tests/test_u5_web.py tests/test_u5_browser.py tests/test_u6_acceptance.py tests/test_u7_progress.py tests/test_u8_budget.py tests/test_u9_drafts.py tests/test_u9_lifecycle.py tests/test_u10_reconnect.py tests/test_u10_restart.py tests/test_u10_pending.py -q
```

必须配置 METRICGUARD_TEST_IMAGE，查询使用实际 Docker 隔离环境；模型提供方可受控。真实模型实验与人工体验单独登记，不能混为同一种验证。

真实模型整体复验（会产生模型调用，使用新的独立运行目录）：

```powershell
uv run python -m experiments.u6_live
```

该脚本通过实际启动命令与浏览器执行简单查询、等待任务恢复、连续澄清及证据定位，核对原始数据并打印记录目录；每次保留新的运行记录。真实模型故障会使本次实验失败，不会自动改用受控模型冒充通过。

## 日常启动入口

已有 Windows 开发环境可双击项目根目录 `start.cmd`，也可在终端执行
`.\.venv\Scripts\python.exe .\start.py`。首次输入 `existing` 沿用明确指定的任务目录，
或输入 `new` 使用不存在的新目录，再选择 `existing` 注册已有兼容快照 `ID=PATH`（空行结束），
或选择 `example` 准备现有开发示例。填写已有镜像名称或固定 ID、端口和模型服务地址，
核对完整路径后输入 `yes` 保存并启动。示例只在确认后生成；已存在的数据不覆盖。

本机设置保存于项目根目录 `.metricguard-local.json`，不纳入 Git，不保存凭据。
相对路径以项目根目录为基准，与调用时所在目录无关。后续启动直接显示并复用该配置。
当前凭据沿用终端环境变量 `ANTHROPIC_AUTH_TOKEN`；启动只检查是否提供，不探测模型。
只有现有 Docker Linux 引擎、固定镜像及真实快照隔离检查通过后，才启动服务并打开浏览器。
终端保留实际地址；关闭网页不会停止服务，按 Ctrl+C 正常停止并等待已接受任务结束。

既有 `python -m metricguard.web_start` 命令及其默认目录保持兼容。

修改设置运行 `.\start.cmd --configure`（或 `python start.py --configure`）。
终端展示修改前后设置，端口改变时提示旧页面需打开新地址；确认前取消不会保存。
修改时空输入沿用显示的默认值；任务目录未改变时，快照直接空行可沿用原映射。
选择另一目录时必须重新指定快照，不会复制或迁移任务。配置损坏会停止并说明问题，
不会改用默认目录；请核对 `.metricguard-local.json` 或恢复其有效副本。

输入镜像名称时，入口会检查并保存对应的固定 `sha256` ID。日常启动不跟随标签变化。
镜像重建后通过 `--configure` 明确更新；缺失时不会自动构建或回退。
