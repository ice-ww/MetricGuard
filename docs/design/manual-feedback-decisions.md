# 手动验收反馈修复：决策记录

状态：用户已确认完整约定与规格测试边界；规格已发布为 [GitHub #22](https://github.com/ice-ww/MetricGuard/issues/22)。

## 已确认规则（2026-10-14，第一轮）

用户对以下四项建议回复“全部同意”。

1. 相对日期按任务创建时的 Asia/Shanghai 日期解释，并固定该解释基准，跨天澄清不改变含义。文本时间与预设窗口冲突时，展示两个具体日期范围供用户选择；不得自动改用数据快照日期。
2. 请求范围的数据不完整时，先说明缺少的数据、可用日期和补齐条件，提供“分析可用范围”和“保留原范围，返回不足说明”的选择。未经用户选择，不自动缩短分析范围。
3. 主要判断展示具体对象、关键数值和证据引用。简单查询直接给数值；诊断还应展示比较依据、反对证据和因果限制。完整事实表另附，正文保留理解判断所需的关键事实。
4. 澄清采用“已知信息＋明确问题＋可选答案”，同时保留自由输入。只问影响下一步的缺失信息，任务 ID、原因代码等内部字段留在日志中。

## 已确认规则（2026-10-14，第二轮）

用户对以下三项建议回复“全部同意”。

5. 本轮支持明确日期范围、“昨天”“前天”“最近 N 天”“本周”“上周”。“最近 N 天”默认指截至昨天的 N 个完整自然日，周一为一周起点。“最近”“前段时间”等含糊表达需要澄清。所有解释展示具体日期，包含今天的范围仍需检查数据完整性。
6. 用户要求分析变化但未指定比较基期时，建议前一个等长窗口，并展示分析范围与基期范围供用户确认或修改。已有明确基期不重复询问；有时间冲突时先解决分析日期，再确认基期。基期不完整时不得静默替换。
7. 用户同意缩小范围后，报告开头同时展示原请求范围和用户确认的分析范围，并明确结论不能推广至原完整范围。诊断重新检查比较条件；比较条件不足时只返回已有事实和无法判断的原因。完全没有可用日期时，说明缺口和下一步，不提供无效的“分析可用范围”选项。
