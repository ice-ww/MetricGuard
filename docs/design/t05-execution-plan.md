# T05 执行计划与公开边界

Issue #6：T05 验证澄清、重放与预算账本（V3）。只实现受控实验，不接诊断流程、模型 API 或冻结任务。

依据既有 Issue/规格预先约定的边界，测试使用 TaskService.create/run/answer/inspect/rerun 以及 Ledger.reserve/mark_sent/settle/inspect。SQLite 为真实磁盘文件，LangGraph 及 SqliteSaver 使用锁定依赖；外部调用用受控 provider 标记文件作为独立观察依据。子进程故障使用 os._exit(73)，不运行 finally 或优雅关闭。

实施按持久化尝试、澄清恢复、输入与活动时间、五个崩溃点四个纵向切片。每片先观察失败，再实现；检查固定字面计数、费用保守预留与真实外部发送标记。类型检查和单文件测试逐步执行。最终验收入口可独立复跑，不由 SQLite 账本自身推算期望发送次数。

Ledger 只接受应用代码分配的 ID 和预算；模型文本白名单不接受预算/状态字段。调用者必须用 mark_sent 原子领取新尝试；sent/unknown 不允许重发，completed 可读取持久化结果。真正重试使用新 attempt_id，失败保留消耗。T07 的最终报告预留在 reserve 同一事务内执行。

单任务活动段在每次预留前累计单调时间，等待用户时没有活动段。崩溃丢失当前段的精确结束时间，重启保守记为活动时间上限，并永久中断旧任务；此值是上界，不冒充实际耗时。外部阻塞调用硬终止由 T03 监督器与后续集成负责，本票不声称该最小图能取消任意外部副作用。
