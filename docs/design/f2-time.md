# F2 时间表达与窗口冲突

Issue #24，审查基线 85ef13b。沿用公开任务服务及终端验收边界。

新任务固定创建时的 Asia/Shanghai 时间解释基准；等待和重启不改变基准。支持完整日期、昨天、前天、最近 N 天以及周一开始的本周/上周；最近 N 天截至昨天，中文起止范围包含结束日，明确半开写法及“结束日不包含”按半开范围处理。自然周包含尚未齐备日期时不能视为完整数据。

解析无法唯一消费的日期表达需要澄清，例如省略年份的混合范围、“截至昨天”、两个日期之间的“或者”。不把部分匹配当作完整范围，不把快照日期作为昨天。日期文字在指标检索前移除，避免把“8日”识别成八日留存。

文本与预设日期冲突时，先显示两个完整范围供用户选择；服务解释编号及自由输入，保存原预设、最终请求、解释来源和锚点。实际报告及终端展示采用日期。重跑使用新的任务创建基准，但保留已经明确的日期，并明确标为沿用；旧任务缺少锚点时不伪造过去的相对日期含义。共享准备结果连同原时间来源一起继承。

本项取代自动缩短请求窗口的旧行为。后续 Issue #26 / [F4 完整性与范围授权](f4-coverage.md) 已加入部分可用时的明确选择：未经授权不执行缩小范围的分析；拒绝或完全不可用时返回具体不足说明。历史报告不改写。
