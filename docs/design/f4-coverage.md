# F4 完整性与范围授权

Issue #26；公开 TaskService 与终端边界，沿用已确认规格。

指标所需数据源由服务确定；新增自然日次日留存与每次日留存用户成本额外要求 D+1 会话齐备。`complete_before` 是 Asia/Shanghai 自然日的排他完整性水位，不是更新 ETA。只有注册表齐备不足以证明留存成熟。可用范围是请求范围与各必需数据源声明的成熟范围之交，不以业务表最早观测行推断完整性起点。

部分可用时保存 `coverage`，列出原请求、可用窗口、缺失指标日期，以及每个不足源当前水位、满足原请求所需水位、成熟条件和下一步。任务等待用户选择使用可用范围或保留原范围返回不足。支持编号、明确接受/拒绝、裸日期及“仅使用”等明确日期命令；日期只能位于已展示的可用范围内。疑问、举例、无法明确解析的表达不构成授权，继续澄清并受原有重复回答/总预算约束。完全无可用日期直接结束，不提供缩小选项。

`requested_window` 保留经时间冲突解决后的原请求；`original_window` 仍表示原始预设，不能混用。`coverage.confirmed_window` 和 `coverage.authorization` 记录用户选择；`actual_window` 只有进入完整性准备后的执行范围才设置。接受后预算耗尽可能有确认范围而没有实际执行范围，报告不得把前者冒充执行证据。重启后的回答和共享预检子任务继承持久化授权；显式重跑创建新任务，重新检查水位并询问是否缩小，不复用历史授权为新任务自动授权。

报告及发布结果携带原请求、确认范围与不能推广至原请求的声明；发布字段来自任务报告，草稿不能覆盖，范围元数据参与发布版本标识。终端在判断正文之前展示声明。历史任务和历史发布不补造授权记录。

分析范围缩小不会自动移动或缩短已确认基期。服务重新检查基期齐备性、先于分析期且不重叠；诊断继续检查各自比较条件，例如按计数判断渠道增长要求等长窗口。不足时保留已有合法事实及限制，不把空候选解释为正常。

复现与测试见 [F4 验证报告](../validation/f4-report.md)。
