## Parent

Part of #22 — 手动验收反馈修复：时间口径、证据呈现与澄清体验。

## What to build

简单查询直接展示数值，四类诊断正文展示实际对象、关键数值、比较依据及可追溯引用；终端和保存报告复用已校验事实，同时保留反对证据和因果限制。

## Acceptance criteria

- [ ] 覆盖简单查询及 A1–A4 四类诊断，主要判断直接使用真实系统、版本或渠道名称和关键值，不仅在附录提供事实。
- [ ] 所有新增事实表述来自已校验结构化证据，引用可定位具体断言和原始结果位置；不得只补未经验证的模型自由文本。
- [ ] 人数、比例及差值单位正确，百分点与百分比变化不混用；显示取整不改动原始证据值或校验依据。
- [ ] 诊断展示比较依据、相关反对证据、未排除因素及因果限制；缺少反对证据不等于证明唯一原因。
- [ ] 终端和保存报告共享事实与说明，正文精简且可访问完整事实表及原始证据；不引入额外模型调用编造事实。
- [ ] 独立 SQL/Python 参考核对关键数值、人群与引用；公开报告和终端入口测试断言用户实际可见内容。
- [ ] 在真实运行中验证至少简单查询和四类诊断的展示；F4 完成后由整体验收核对不足说明与范围标注，不以此人为阻塞本任务。

## 验证与范围

遵循父规格已确认的 TaskService 公开行为和必要终端验收边界，测试用户可观察行为，不耦合私有函数或 Prompt 原文。开发任务采用先失败后通过的回归测试，进行类型检查、适用的真实查询/模型验证和独立审查；保留证据及未通过项。核心业务规则由服务执行，沿用证据、隔离及预算边界。此任务不建设 Web/桌面交互界面。
