## Parent

Part of #22 — 手动验收反馈修复：时间口径、证据呈现与澄清体验。

## What to build

支持约定时间表达，持久化任务创建时的 Asia/Shanghai 时间基准；文本与预设窗口不一致时让用户明确选择，使确认日期贯穿查询、证据和报告。

## Acceptance criteria

- [ ] 支持明确日期范围、昨天、前天、最近 N 天、本周、上周；最近 N 天截至昨天且为完整自然日，周一为周起点；含糊或无法唯一解释的日期必须澄清。
- [ ] 任务创建时固定时间锚点，同一任务跨午夜等待或恢复不改变相对日期；不得改用历史快照日期解释昨天。
- [ ] 冲突时展示文本和预设对应的具体日期，未选择前不得执行依赖该选择的分析；相同范围不重复询问。
- [ ] 用户选择或修改后，实际 SQL、证据和报告与确认日期一致；明确起止边界，完整性不足不静默改写日期。
- [ ] 旧任务读取不伪造时间锚点或授权；重跑作为新任务时明确展示新解释及沿用的明确范围，保留来源，不能隐含改变已明确日期。
- [ ] 从公开入口覆盖跨日、月末、年末、周界、历史快照冲突、含糊日期及相同窗口；用独立日期期望核查实际查询。
- [ ] 通过终端完成昨天与预设一周冲突的真实运行，保留选择过程、SQL 和结果。

## 验证与范围

遵循父规格已确认的 TaskService 公开行为和必要终端验收边界，测试用户可观察行为，不耦合私有函数或 Prompt 原文。开发任务采用先失败后通过的回归测试，进行类型检查、适用的真实查询/模型验证和独立审查；保留证据及未通过项。核心业务规则由服务执行，沿用证据、隔离及预算边界。此任务不建设 Web/桌面交互界面。
