## Parent

Part of #22 — 手动验收反馈修复：时间口径、证据呈现与澄清体验。

## What to build

交付已知信息、明确问题和可选答案组成的澄清交互，保留自由输入；用户回答后在同一任务继续。交付可版本控制的终端验收入口，为后续日期、基期和范围选择复用。

## Acceptance criteria

- [ ] 已提供日期但缺少指标时只询问指标；普通交互不输出内部 JSON、问题版本或原因代码，日志保留排查信息。
- [ ] 终端与核心服务使用一致的澄清内容，选项和自由输入均可通过公开 answer 行为继续；正确保留已确认上下文。
- [ ] 调整全任务固定两轮限制，允许后续不同阶段的合法澄清；无效反复回答仍有明确、可验证的有限停止策略，不重置执行预算。
- [ ] 重复、过期和并发败选答案不得触发重复执行；等待不计活动时间，重启后继续同一待答任务。
- [ ] 可版本控制的终端入口可在新检出环境按说明运行，不依赖未跟踪操作脚本；业务规则不放在展示层。
- [ ] 通过 TaskService 及终端入口验证多次有效澄清、无效回答停止、恢复与旧任务兼容；不伪造旧任务缺失的用户确认。

## 验证与范围

遵循父规格已确认的 TaskService 公开行为和必要终端验收边界，测试用户可观察行为，不耦合私有函数或 Prompt 原文。开发任务采用先失败后通过的回归测试，进行类型检查、适用的真实查询/模型验证和独立审查；保留证据及未通过项。核心业务规则由服务执行，沿用证据、隔离及预算边界。此任务不建设 Web/桌面交互界面。
