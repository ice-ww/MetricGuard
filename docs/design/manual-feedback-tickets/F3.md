## Parent

Part of #22 — 手动验收反馈修复：时间口径、证据呈现与澄清体验。

## What to build

变化分析未指定基期时提出前一个等长窗口，用户可确认或修改；明确基期沿用且不重复询问，简单查询不增加无关比较确认。

## Acceptance criteria

- [ ] 先解决分析日期冲突，再提出前一个等长窗口作为基期建议；展示两段具体范围，确认或修改后才执行依赖比较口径的分析。
- [ ] 已明确提供的基期不重复询问；简单数值查询不强加比较基期。
- [ ] 用户修改基期后，实际 SQL、结构化事实、比较标签与报告一致，不只改变提示文字。
- [ ] 基期不完整时不得静默换成其他日期或强行诊断；后续不足说明与范围授权由依赖本任务的 F4 完成。
- [ ] 公开任务行为与终端验收覆盖默认建议、修改、明确基期、无关简单查询及日期冲突后确认基期的连续流程。
- [ ] 独立查询按实际确认的两段窗口核对人数、分子分母和结果；记录真实模型运行证据。

## 验证与范围

遵循父规格已确认的 TaskService 公开行为和必要终端验收边界，测试用户可观察行为，不耦合私有函数或 Prompt 原文。开发任务采用先失败后通过的回归测试，进行类型检查、适用的真实查询/模型验证和独立审查；保留证据及未通过项。核心业务规则由服务执行，沿用证据、隔离及预算边界。此任务不建设 Web/桌面交互界面。
