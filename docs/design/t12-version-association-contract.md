# T12 版本崩溃关联诊断契约

公开边界沿用已批准的 `TaskService.create/run/report/trace`。调用 `mode='diagnose'`，当前窗口必须采用新增用户自然日次日留存口径；程序先按水位收窄成熟窗口。

## 取证

现有 profile 能力新增三种参数组合，不新增第七个工具，不绕过 SQL AST、安全容器、调用预算或结果校验。

| kind | table / column | 返回内容 |
| --- | --- | --- |
| cohort_health | users / registration_version | 当前、紧邻的等长前期；注册系统/版本分组的新增、去重 D1 留存、去重首日崩溃人数及比率 |
| crash_versions | sessions / version | 同一 cohort 和注册首日条件下，注册归属与实际崩溃系统/版本分别保留；每组去重用户 |
| releases | release_calendar / version | 当前窗口结束前的发布日历，包括旧版发布时间 |

模型根据实际证据选择动作顺序，也可继续安全 SQL 或停止。三个 profile 都是通用业务查询，无异常编号、种子、注入参数或黄金答案输入。日期由已成熟窗口产生，不再多减一天。前期不存在的新版本没有行，不虚构零留存率。前期事实的上下文使用前期窗口；完整结果覆盖前期至当前期。

实际 SQL、数据类型和所有结果行持久化。为了降低重复提示消耗，模型看到标准 profile 的动作参数及全部结果行，模板 SQL 不重复塞入提示。自由 SQL 仍保留原有模型视图。

## 发布

使用这些 profile 后，程序发布全部数值事实并通过现有证据校验，不再次调用模型生成数值。受限解释规则只读取完整、未截断的可信 profile，任意自由 SQL 即便列名相同也不能冒充可信 profile。无需降低预算来完成报告。

版本候选要求：当前与前期均有实际用户；受影响系统总体留存下降；该注册版本较同系统前期和同期其他版本留存低，且比同期其他版本首日崩溃率高；每个差值采用 T04 `t04-v1` 的 5 个百分点业务阈值。必须存在同期其他系统对照、窗口内唯一匹配发布记录、实际崩溃系统/版本与注册归属一致且崩溃受影响人数可核对。实际运行版本错位时保留分离的事实并降级，不直接归因到注册版本。

报告保留支持事实、对照事实及其前期记录、未排除混杂因素、比较样本量和描述差值；所有记录指向持久化 evidence 的行。对照证据使用中性文字，不假设对照没有下降。程序仅生成“相关候选解释”，不接受模型自由文本作为已经验证的原因。

`association_candidate` 只表示以上描述规则满足；`no_supported_candidate` 表示完整资料没有产生满足规则的候选，不能读作“确认正常”；`insufficient_evidence` 保留缺失的资料及已有事实。`facts_available` 也不等于完整诊断验收通过。

没有独立同质 Bernoulli 抽样证明，统计调用传入 `independent=False`，区间为空，禁止显著性断言。自适应下钻、未排除混杂和新版本没有前期样本的限制显式保留。解释合理性仍需人工语义核验，程序不代替用户确认。

## 验证边界

公开任务服务测试使用真实受限 SQL 容器，只控制外部模型 HTTP 响应。cohort 数值由独立 Python membership oracle 核对；正常对照不得强报候选，实际崩溃版本错位必须降级，部分 profile 只能发布部分事实。开发变体、真实模型及独立审查的最终结果写入对应验收报告，不能仅凭本设计文档关闭任务。
