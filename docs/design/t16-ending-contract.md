# T16 任务结束与分析结果契约

沿用父规格已确认公开边界，不新增模型权限或预算配置入口。`status` 表示执行（ended/failed/interrupted/waiting 等），兼容的 `outcome` 表示事实可用或停止原因；新增 `analysis_result` 与报告中的同名字段表示分析结果，并以 `analysis_concluded` 事件保存相同结论。事实校验通过不自动说明诊断成功。

| analysis_result | 范围 |
| --- | --- |
| supported_descriptive_candidate | 完整相关画像支持观测快照的描述性候选；不证明总体推断或因果 |
| no_supported_anomaly | 仅完整、对齐的双链路播放实例在所查询窗口内未达到既有采集缺失开发规则；不表示全局无异常 |
| insufficient_evidence | 没有可核验事实、缺少相关证据、质量不足，或二元用户比较的独立性/精度尚未建立 |
| refused | 模型明确拒绝，或动作/SQL 请求超出程序支持的能力边界 |
| budget_exhausted | 工具、模型、Token、活动时间或未知用量保护停止任务 |
| unsupported | 指标检索确认不支持 |
| facts_available | 普通查询已发布可核验事实，未执行诊断 |

`no_supported_candidate` 是单项描述性画像规则的结果，不直接映射为“无异常”。尤其系统、渠道、版本的分组 SQL 计数不能自动证明独立同质抽样及区间精度；正常留存开发实例可正确结束为 insufficient_evidence，报告明确未建立总体推断的充分性。沿用 t04-v1 的5pp与20pp，不临时校准新阈值。统计接口的精度/质量边界继续由既有独立参考及全仓测试复验。

预算耗尽、拒绝与其他有限结束保留已核验事实、数值描述和未决问题，清除未完成候选、设置 partial 范围。不要求用额外模型生成完整报告。拒绝动作和政策拒绝均记录 Trace；前者在调用查询执行器前拒绝，后者由受限执行器拒绝且失败调用计费。模型只能请求 action/refuse/reason，不能写 analysis_result、路由、工具表、资源或累计预算。

用户输入和可见字段中的注入文字都作为数据。受控 HTTP 可以模拟模型完全服从恶意文字后发起越权动作，用于验证程序边界；真实任务另外记录模型实际反应。若模型忽略注入而正常提供有限结果，这属于边界保持，不要求它必须触发 SQL 拒绝。

开发验收：普通正常播放、独立证据缺失、正常留存精度未建立、保留画像后的预算耗尽、用户越权与渠道字段注入，共六类；独立原始数据参考复核正常/不足/有限事实。测试只观察公开任务状态、报告、Trace及提供方发送边界，不解析 Prompt 分隔符。
