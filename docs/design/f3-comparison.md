# F3 比较基期确认与查询一致性

Issue #25；审查基线 9808f67。沿用 TaskService 公开入口与终端边界。

先解析分析日期、解决日期冲突并明确指标，再确认变化分析所需的基期。默认建议前一个等长窗口，展示两段半开日期；编号、确认文字或自由输入均由服务处理。用户明确提供的基期沿用，不重复询问。基期文字可写在问题末尾，例如“新增用户自然日次日留存变化，基期2026-06-01至2026-06-03”；自然语言范围包含结束日。API 的 comparison_window 与 CLI 的 --comparison-window 使用半开范围。文本与参数基期冲突时需要选择，不静默决定优先级。

比较范围独立保存为 comparison_window，并随共享准备、重跑、模型材料和报告传播。确认基期后，query 模式也使用可返回结构化比较事实的行动流程，最终仍按查询模式限制结论。普通查询不要求确认无关基期；模型选择比较模板但没有已确认基期时，模板只查询当前期，不自动扩展日期。

业务比较模板同时使用基期起止日：两个范围以 OR 连接，不查询中间空档。各行窗口、previous/current 标签和事实上下文使用实际范围。播放模板的事实日期同样从已确认范围取得。原始自由 SQL 保留既有 requires_independent_reference 标记；机械校验不等于自动证明 SQL 的业务含义。

当前受控比较模板支持先前且不重叠的基期。重叠或晚于分析期的范围保留原选择并明确停止，不擅自换日期。基期未齐备时停止；F4 补充详细缺口及范围授权。允许不等长的完整窗口提供各期事实及描述性留存率，但渠道总量增长规则需要等长窗口，不等长时不发布增长贡献候选。没有把总人数差除以天数来悄悄改变用户选择的业务指标。

旧诊断测试的固定前期现在通过 API 明确提供；不再依赖隐式前期。旧自动缩窗测试按 F2 已批准的新约定检查停止。模型停止说明不能冒充已验证限制的测试仍保留真实模型边界和实际查询，只把已禁止的自动缩窗改为用户明确选择的不等长范围。

执行预算、安全策略和 SQL AST 白名单不扩展。新实验是开发定向验证，不使用或重新宣称既有冻结集为未见验收。
