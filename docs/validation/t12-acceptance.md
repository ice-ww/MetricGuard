## 范围与证据

现有动态诊断循环增加三种经验证的业务画像参数：cohort_health、crash_versions、releases。报告按持久化证据输出成熟留存、注册系统/版本、实际崩溃系统/版本、首日去重受影响人数、发布日和旧版本/其他系统对照。受限规则只给关联候选解释，不输出因果断言；自由 SQL 不能冒充可信业务画像。

独立参考 `experiments/t12/reference.py` 读取原始 users/sessions/release_calendar，以 Python 集合核对，不复用产品 SQL。开发实例在日期、版本及强度上变化：

| --- | --- | --- | --- |
| 2026-01-08 至 01-15 | 2.0 | .65 | 420 / 100 / 270 |
| 2026-03-10 至 03-17 | 4.7 | .35 | 420 / 164 / 135 |

全部为开发材料，没有使用冻结验收集。私有注入参数、参考结果和场景编号不传入 TaskService 或模型。明细见 t12-reference.json。

受控模型边界加真实 Docker 的三个变体：75/75 计数及比率、75/75 事实窗口、3/3 证据联合窗口通过，见 t12-controlled.json。这些记录产生于报告边界修正前，证明数值计算，不代替最终版本验收。

首次真实问题同时提及多个指标，现有检索返回澄清，0 模型调用。随后明确留存问题的三个真实运行均完成 3 个画像和停止，各 4 模型 / 6 工具，实际 Token 为 9066、9151、9039；独立数值、崩溃分组和发布日共 99 项通过。原始记录 t12-real-initial.json 保留；报告对照用语和缺失判断后来修正，因此不以初始报告作为最终发布证据。

## 审查修正与限制

两轴子代理指出：有对照行不等于反对证据；缺少必需对照不能默认为正常或无候选。实现改为中性呈现对照及其前期事实，并在缺必要资料时说明无法判断。另验证实际崩溃版本与注册版本错位时保留分离事实并降级。

T04 的 5 个百分点业务阈值只用于探索性筛选，不是显著性。无法证明独立同质抽样，所有统计比较使用 independent=False，保留样本量/差值，区间为空。当前新版本前期无记录不当作零。人工候选解释语义核验尚未由用户确认；子代理和程序核验不代替该人工判断，正式 T20 验收需单独记录。

## 最终实验

`t12-real-final.json` 保留三例异常及一例正常的完整真实模型结果与独立检查。每例 4 次模型、6 次工具；实际 Token 依次 9174、9139、9096、9212。共 100 项 cohort 数值、20 项实际崩溃分组、12 项发布记录核对通过，三例版本候选正确对应 2.0/4.7/9.2，正常实例 no_supported_candidate。全部数值事实通过引用校验，解释只作关联，区间为空。

`t12-resources.json` 为本票集成后的真实资源复验：5 秒查询超时后确认回收、保留已知事实、没有隐式修复调用，同服务下一任务成功，4 次受控提供方请求账本一致。最终一个修复仅处理“同系统前期和同期旧版均缺失”的降级分支，不改变上述完整数据路径；该分支单独运行 RED → GREEN。

独立 Spec 审查原两项问题已修复，独立执行五项常规及三项缺失反例均通过，同意关闭。Standards 最终零未解决硬性违规，同意发布；非阻塞建议为 cohort 日期/首日条件的重复 SQL 可后续集中维护。T11 + 原 T12 17 项通过；最终新增缺同系统全部对照反例 1 项 RED → GREEN，mypy 52 文件及锁文件检查通过。全仓 **277 passed in 405.55s**（采集于最后新增反例之前）；最后缺对照分支另有 1 项 RED → GREEN，当前共 278 项覆盖。最终真实记录再次由 Spec 子代理独立核对版本、窗口、全部账本与限制，通过。符合本票关闭条件。
