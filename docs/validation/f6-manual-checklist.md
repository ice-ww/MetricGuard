## 准备与启动

在仓库 PowerShell 打开，Docker Desktop 的 Linux 引擎保持运行，当前终端需已有 `ANTHROPIC_AUTH_TOKEN`（不要将密钥写进报告或聊天）。每次只运行一个验收任务。示例数据是可重建的开发快照，不是线上数据或正式未见验收集。

```powershell
Set-Location 'D:\ai coding\metricguard'
$env:PYTHONUTF8='1'
$env:METRICGUARD_TEST_IMAGE='sha256:4cadf9b4afae2394df26a2d518ab7d68fbbc4e086081f4273c45410fae456cb0'
uv run python -m experiments.f6_manual --case A1
```

入口会打印会话配置路径，随后直接调用产品终端。所有示例预设请求范围为 **2026-08-10 至 2026-08-17（结束日不包含）**。变化分析会先建议基期8月3日至10日；按1确认或输入其他明确范围。不要使用旧 artifacts/manual-acceptance/start.cmd 来验收新交互，该旧辅助脚本保留作历史材料。

## 逐项体验

把上面命令的 `--case` 替换为下表值。每次创建独立任务与数据。

| case | 操作 | 应观察到的行为 |
| --- | --- | --- |
| conflict | “昨天”与8月预设窗口冲突时，先读两个具体日期，选择2保留预设，再选择1确认基期 | 确认前不查分析数据；终端和报告实际日期为8月10–17日，并显示基期；不能静默采用日期 |
| empty | 同样冲突时选择1使用实际“昨天” | 若昨天晚于快照齐备截止，直接说明无可用日期、缺少会话/成熟条件、补齐条件和下一步，不提供无效缩小选项 |
| chain | 先选择2保留预设，确认基期1，再选择可用范围1 | 依次澄清三阶段；原范围8月10–17日、确认范围8月10–13日、基期8月3–10日均保留；明确不能推广到原范围 |
| coverage | 分别用两个新任务选择1和2 | 1只分析8月10–13日；2保留原范围并返回不足，不能把局部数据当完整结论；说明D+1会话条件及可用/缺失日期 |
| clarify | 回答“我想看新增用户自然日次日留存，使用刚才提供的日期窗口” | 只问缺失指标，已知日期可见，不再要求补日期；普通提示不显示question_id/version等内部JSON |
| simple | 无需回答澄清 | 直接显示新增人数、日期和A引用，不要求确认无关基期 |
| A1 | 确认建议基期 | 直接显示Android版本2.0和对照版本/系统的人数、留存与崩溃指标；候选相关解释不写成确定因果 |
| A2 | 确认建议基期 | 渠道名称、人数、留存、每新增/留存用户成本及单位清楚；零分母不显示为0% |
| A3 | 确认建议基期 | 观测完成事件与独立进度数值并列，保留其他系统/版本对照及未排除因素 |
| A4 | 确认建议基期 | 分系统留存、结构占比与标准化指标有直接引用，不能把总体与分群混为一谈 |

“昨天”和“最近7天”始终按**任务实际创建时间**解释。未来日期变化后，empty是否无可用仍以终端显示的水位为准，不能拿本文预设日期替代时间锚点。自由问法可加 `--question '你的问题'`。上述检查关注口径和证据，不要求模型每次选择同样查询顺序或完全相同文字。

## 暂停与恢复

在澄清处直接回车，会保留等待任务并打印任务ID。复制开始时的会话配置路径和任务ID：

```powershell
uv run python -m experiments.f6_manual --session '完整路径\session.json' --task '任务ID'
```

同一任务恢复时应保留原日期解释基准；即使跨日，“昨天”也不能重新漂移。该命令使用原状态目录，不重建快照。也可以不加 `--task` 使用同一会话创建新任务。
