## 交付范围

- `python -m metricguard.web_start --demo` 启动；启动前核查模型凭据、固定镜像、Docker Linux 引擎与真实快照业务结构。管理员可使用 `--snapshot ID=PATH`、`--base-url`、`--state-dir`；网页不接受这些执行配置。
- 仅监听 127.0.0.1；Host/Origin/跨站检查、会话操作令牌、静态资源白名单及 CSP。模型凭据和原始异常不传入页面，问题和结果以纯文本显示。
- 长期单一 TaskService 持有状态目录；后台执行期间 HTTP 仍可读取状态。持久化操作标识去重，重复提交返回同一任务；其他操作忙碌时拒绝，不创建排队任务。等待澄清释放执行槽。
- 示例问题及日期可编辑；创建、状态、基础报告与已知任务链接刷新/重开。页面关闭不取消执行；旧页面响应不能覆盖新问题。正常运行显示墙钟历时，异常结束时间未知时明确说明未完整记录，不计入停机时间。
- 不改动既有分析、时间澄清、发布或预算规则。澄清回答、历史、分层证据与重跑继续由 U2–U5 交付。

使用步骤见 [本机界面使用说明](../local-ui.md)。

## 自动验证与红绿记录

测试边界为真实浏览器/公开 HTTP -> TaskService -> 实际持久化与 Docker 查询；只有外部模型提供方使用受控响应。额外的未执行查询场景使用占位快照。Docker 工作负载串行运行，无必要集成跳过。

- 初始 HTTP 红：web 模块尚未存在；实现后 1 项通过。
- 启动红：启动模块缺失；补齐后启动/请求限制/等待释放等 3 项通过。
- 浏览器首次完整查询通过；随后新增重开表单保持测试，先发现表单为空，修复后通过。
- 审查红：延迟 GET 覆盖新编辑问题、管理员端点参数缺失，两项均实际失败；修复后的定向检查 **7 passed**。
- 中断红：真实子进程进入模型调用后强制结束，再打开同一状态目录，原实现错误返回增长的历时 2.9；修复后 **1 passed**，状态中断、历时为 null。测试最初使用占位快照无法进入模型，纠正为真实业务快照后才取得有效红绿证据。
- 并发 HTTP：Barrier 同时发起两项不同操作，恰好 202/409；重复接受操作返回原任务 ID，结束后重启也不重复模型调用。
- 浏览器双击仅执行一次；查询未完成时关闭页面，重开原任务并刷新，受控模型总调用仍为 2。问题中的 HTML 字符串不执行脚本。
- 类型检查：`uv run mypy`，93 个源文件通过；`uv run mypy experiments/u1_live.py`，1 个文件通过。

最终命令：`uv run pytest -q --junitxml=artifacts/u1-full-suite.xml`，退出码 0。运行环境、依赖版本与最终源文件 SHA256 见 [环境记录](u1/environment.json)。

各次 pytest JUnit 原文以 gzip 保留，计数、耗时及原文 SHA256 见 [测试清单](u1/tests.json)。首次未进入模型的测试脚手架失败不作为有效产品红测试；归档的是修正后的有效红绿运行。
