## 启动

前提：在仓库 PowerShell 中，Docker Desktop Linux 引擎已运行，Python/uv 依赖已准备，当前终端已配置 `ANTHROPIC_AUTH_TOKEN`。密钥不用填到页面或反馈中。首次设置固定镜像：

```powershell
$env:PYTHONUTF8='1'
$env:METRICGUARD_TEST_IMAGE='sha256:4cadf9b4afae2394df26a2d518ab7d68fbbc4e086081f4273c45410fae456cb0'
```

从 `D:\ai coding\metricguard` 一条命令启动：

```powershell
uv run python -m experiments.u6_manual
```

打开终端显示的地址，默认 [本机界面](http://127.0.0.1:8765)。端口被占用可加 `--port 8766`。此入口准备固定开发数据并调用正式启动器，使用 `artifacts/u6-manual/state` 保存任务；再次启动不会重建原数据。`demo` 是普通查询快照，`diagnosis` 是分系统留存变化示例；它们不是生产数据或新的冻结验收集。

如要核对运行期间关闭页面，开始查询后关闭标签页再从同一地址打开历史；页面关闭不取消服务任务。无需手工强杀进程来制造中断，该场景已有独立子进程故障测试，证据见覆盖表。

## 停止、恢复及配置问题

- 正常停止：在启动终端按 Ctrl+C，等待本次执行结束、进程退出后再启动。等待澄清不会触发模型执行。
- 意外中断：仍用原状态目录启动；运行任务显示中断，未知调用不自动重放。明确点击“创建关联重跑”才创建新任务。
- 忙碌：每个服务只执行一个任务，不排队。等待中的任务释放执行位；忙碌提示后稍后重试。
- 缺少凭据、镜像、Linux 引擎或快照：按启动提示修正。不要把异常处理成静默跳过或改用不受隔离的查询。
- 端口占用：换端口；目录占用：退出持有同一目录的旧服务。不要并行启动两个服务共用同一状态目录。
- 快照缺失或不兼容：保留原任务目录，修复原快照配置；不要用新数据覆盖旧文件后冒充原结果。需要独立新验收可传 `--state-dir artifacts/u6-manual-new/state`。
- 仅本机单人使用；无排队、主动取消、任意文件上传、网页密钥设置或跨任务连续聊天。美观与一般文字润色留后续，功能错误需记录并修复。
