# T20 前置集成补修与开发验证

Issue: https://github.com/ice-ww/MetricGuard/issues/21

用户选择先补修前置集成，再运行正式三轮。本文仅记录开发材料，不构成冻结验收通过；原始预检失败保留于 t20-preflight.md/json，各次开发评分与配置保留于 [t20-development.json](t20-development.json)。

## 补修范围

- 补齐独立计数指标检索、含指标全名的问题、增长成本综合问题和真实澄清续跑。
- 同一预检材料及消耗继承给 Agent/基线；仅能确定尚未派发的 Agent 查询允许一次计费重试，基线不重试。
- 真实画像进入发布契约，按可信 SQL 定义映射指标上下文；派生事实保留来源。采集缺失必须经过独立双链路完整性和对齐检查。
- 发布使用原始文件身份，评测投影保留原始证据、文件 SHA 与逻辑身份，校验转换前后哈希。
- 基线仍先密封完整查询批次，执行后仅一次报告调用。报告改用数值列选择，可信代码展开实际单元格，减少重复输入和截断。
- 当前期被完整性截短时保留原请求决定的基期，披露不足，不发布覆盖整个请求窗口的候选。
- 安全回执绑定最终代码、环境、测试源码及完整收集清单，严格检查 JUnit 身份、数量与失败/跳过。
