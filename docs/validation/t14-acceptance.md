# T14 播放采集异常验收

Issue #15；上一票 #14 在 dae94d6 发布并关闭后开始。环境：Python 3.12.10、DuckDB 1.5.6、sqlglot 30.22.0、pytz 2026.5；Docker `sha256:4cadf9b4afae2394df26a2d518ab7d68fbbc4e086081f4273c45410fae456cb0`。真实提供方为 DeepSeek Anthropic 兼容端点，模型 deepseek-flash。默认安全、SQL、资源与预算边界未改变。

## 行为与独立参考

通过现有 profile 能力提供播放事件与独立进度画像，两者均执行隔离只读 SQL。按 play_id 去重，重复观看保留不同实例；观测完播、独立完播和有效播放分别计数。canonical SQL AST 为事件 320、进度 506，保持 512 节点上限。

独立 `experiments/t14/reference.py` 读取原始记录，用 Python 分组和集合核对播放对齐、计数与守恒，不调用产品画像查询。每个生成快照有 8440 条开始上报、7632 个不同播放实例，两个评测窗口共 6672 个播放实例。另有实际 DuckDB 冲突开始夹具，验证最早非空开始时间跨窗口归属和歧义排除，见 t14-reference-conflicting-starts.json。

原始 `independent_complete_without_event` 仅表示差异。只有两链路完整且会话、实例、时长及观察时点有效，才发布 `missing_completion`。完成观察时间必须严格早于遥测和事件两者的完整截止时点；不能仅凭开始窗口已齐备判断窗口尾部的完成事件缺失。缺遥测、错位、空会话系统/版本/开始时间、冲突开始、异常时长、空窗口或越过水位均阻止候选，保留不确定性。

## 审查与最终检查

新增 14 项公开服务测试。错位独立完成计数和空窗口状态有实际 RED→GREEN；其他边界按回归验证记录，不虚报全部测试均先失败。审查发现并修复早停缺 watermarks 导致的 KeyError、误导性原始缺失命名、逐期证据窗口、空会话字段及跨源完成水位问题。旧合并测试唯一失败是测试把 JSON list 与 tuple 比较，修正后独立复验通过。

Spec 子代理独立早期 11 项通过（96.24 秒），最终四项边界通过（42.02 秒），并独立核验全部七个真实记录的计数、引用、候选及用量，结论可发布关闭。Standards 零未解决硬性违规；非阻塞建议为未来集中画像种类与窗口分支，避免重复维护。

t14-resources.json 是最终服务实际资源复验：查询超时、回收确认、已有事实保留、无隐式修复、同服务下一任务成功，4 次提供方请求与账本一致。mypy 59 个文件、锁文件及 diff 检查通过。最终全仓 **300 passed in 561.05s**。符合本票关闭条件。

## 限制与重放

当前 schema 没有地区字段，本票通过不同实际版本验证，不虚构地区支持。真实请求使用当前知识检索支持的精确问题“完播率”；更宽泛的自然语言表达不在这些真实记录的证明范围内。播放实例不是独立用户，比例仅作描述，不套用用户级独立二项检验或置信区间。

候选仅是关联，不证明采集故障因果；两链路同步偏差及独立遥测自身错误仍未排除。候选解释与反对事实是否充分仍需人工语义核验，子代理及自动测试不代替用户确认。全部为开发材料，正式冻结三轮留给 T20。

生成：`uv run python -m experiments.t14.reference --build <fresh-directory>`。真实请求复用 `experiments.t12.run_real`，传入快照、窗口、上述镜像和 `--question 完播率`；凭据仅从本地 ANTHROPIC_AUTH_TOKEN 读取。核验：`uv run python -m experiments.t14.check_result --help`。公开测试：设置 METRICGUARD_TEST_IMAGE 后执行 `uv run pytest tests/test_t14_service.py -q`；资源复验使用 `experiments.t11.check_resources`。每次输出使用新目录。
