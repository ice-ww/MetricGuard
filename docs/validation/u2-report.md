## 确定性公开边界验证

模型仅在提供方边界受控，HTTP、TaskService、持久化、浏览器与涉及查询的 Docker 隔离执行均为真实组件。

- 六阶段流程：输入“昨天用户表现有什么变化？”，创建锚点固定 2026-01-15，表单窗口 [2026-01-08, 2026-01-15)。选择表单日期，回答“留存”“新增用户”“自然日次日”，确认基期 [2026-01-01, 2026-01-08)，最后明确接受可用范围 [2026-01-08, 2026-01-11)。查询前没有模型调用或证据，最终同一任务保留 6 条答案；累计工具调用 9、模型调用 2，预算限制未重置。受控模型只查询并停止，该用例最终为 insufficient_evidence，不将其称为诊断语义验收通过。
- 独立参考从原始 users/sessions 读取本地注册日与活动日，以 D+1 集合计算两期、两系统人数与留存；逐行核查实际 evidence 窗口、人数及留存。
- 拒绝缩小：保持原请求，输出证据不足，无模型调用和证据。无可用数据：说明会话数据缺口和可用日期，无回答选项。简单查询：只补充“新增用户数”，无比较基期，独立 SQL 计数与页面相符。
- 公开 HTTP 覆盖重复操作、不同内容复用 key、过期问题版本、并发竞争、忙碌不消费答案、非法字段/空回答/错误版本/来源/非本任务访问。
- 浏览器模拟真实 POST 已被接受但响应丢失；刷新读取新问题，旧标签页答案被拒绝；不产生重复回答。
- 实际子进程在回答模型调用期间强制退出。新服务读取原目录后显示中断和未知历时，相同/新操作均不重放，任务和调用记录不变。
- 实际删除该测试任务的检查点文件，回答前置校验失败；页面适配层显示失败并隐藏回答，同操作重试被拒绝。底层任务无法完成回答时，不把适配层操作失败伪装为等待中的可执行操作；关联重跑留给 U5。

各受控场景的最终任务 ID、输入、结果及完整任务归档见 [运行清单](u2/controlled-runs.json)，[六阶段最终页面](u2/continuous.png)。

## 红绿过程

1. 回答协议与入口缺失：公开接口红测试 KeyError clarification；实现后通过。
2. 浏览器没有澄清表单：真实浏览器红测试找不到问题展示；实现后流程运行成功。首次独立核对误把基期行也按本期过滤，测试参考报 828 与 360 不符；纠正参考按 period 分开两期后通过，未为此修改产品计算。
3. 审查发现检查点丢失后误报 waiting：真实存储故障红测试复现；补充回答失败的持久终态后通过。
