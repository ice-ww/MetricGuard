## 实现与独立参考

channel_health 通过相同受限 SQL 工具输出前后期渠道用户、D1 留存、同注册窗口支出与两种成本。零分母为 null，缺支出不当作零；支出水位未覆盖窗口则拒绝完整画像，不将用户与费用窗口分开缩短。

初版包含所有派生量的 SQL 超出 512 AST 节点限制，保留拒绝规则，将占比、增量和增长贡献移到程序报告的 channel_metrics。每项附本渠道及总分母的原始证据引用，显式标记程序派生。净增为零时贡献为 null；负增长不称拉动增长。

独立 experiments/t13/reference.py 仅 raw SELECT 与 Python 集合，核验去重留存、人数/支出守恒、份额及贡献，并把原始支出缺失保留为 null。开发参数只进入生成器和私有验收材料，未进入模型或产品。三个实例变化日期、渠道、强度及单位成本：

| 本期窗口 | 渠道 | 当前新增 / 留存 | 每新增成本：基期 → 本期（分） |
| --- | --- | --- | --- |
| 2026-01-08 至 01-15 | paid | 2520 / 272 | 100 → 200 |
| 2026-04-10 至 04-17 | partner | 1680 / 321 | 100 → 100 |
| 2026-09-12 至 09-19 | search | 3360 / 273 | 100 → 50 |

三个受控模型 + 真实 Docker 实例的 252 个单元格及派生引用通过，见 t13-controlled.json；独立参考见 t13-reference.json。额外实际删除一个当前期渠道支出记录，验证用户/留存保持、支出与两成本为 null，前期支出不变。

## 真实模型与审查

t13-real-final.json 保留三例异常和一例正常的全部真实结果。每例 2 模型 / 4 工具，实际 Tokens 3658、3636、3641、3614，与账本一致。共 336 个单元格通过独立参考，三渠道按实际数据定位，正常未误报。单位获客成本的变化分别 +100、0、−50 分，未假定必然上涨；不把低留存称为造假，不引入激活口径。

Spec 子代理独立执行全部 8 项公开服务测试：8 passed in 79.31s；覆盖数值、成本持平、费用水位不足、零增长、零留存、缺对照、缺支出及正常。另独立复算三个受控实例及四个真实模型报告的数值、派生引用、成本变化和用量，验收通过，同意关闭。

Standards 审查零未解决硬性违规。非阻塞 possible Repeated Switches：画像种类在服务中的窗口、口径与限制分支后续可集中维护。只出现渠道画像时不会触发版本诊断；原预审提示已由当前 kind 过滤排除。

## 限制与重放
