# T10 验收结论

2026-10-13，Issue #11「打通澄清、中断与重跑」。本票在 T09 提交 `0b68abd` 推送并关闭 Issue #10 后开始。

## 公开行为及实际验证

9 项公开服务测试与 6 项进程/恢复测试均已由独立规格审查者执行通过，使用真实 LangGraph、SQLite、SDK 和 T09 最终 Docker 镜像。不是冻结验收集。

- 最多两轮澄清；实际 interrupt 暂停且等待不计活动时间；合法答案在同一任务继续，保留此前调用与预算。
- 过期、重复及两个线程并发提交同一问题答案只允许一次继续；不支持口径直接结束。
- 等待任务跨服务重启可继续；运行中任务在五个真实进程退出点均变为中断，保留证据、Trace 和累计账本，没有自动续跑。
- 未知 usage 跨重启仍保留预留、费用未知；已完成或已记录未知结果的同 attempt 在最终服务账本上重放，不新增外部请求或计费。
- 显式重跑创建新任务和独立预算，parent 指向旧任务；旧记录不变。新任务数值核对原始用户集合参考。
- T09 旧持久化格式兼容，以及合法长问题澄清后重跑均先复现失败，再修复并通过回归。

[进程实验与机器记录](t10-process-recovery.md)；[设计、公开入口及各次测试记录](../design/t10-clarification-recovery.md)。T10 没有更改 SQL 镜像或放宽权限；T09 的最终镜像权限 92/92、资源 56/56 记录仍对应同一实际镜像。

## Standards

独立子代理最终硬性违规 0、阻塞 0。问题/版本/checkpoint 核验和原子状态转换维持预算及状态边界；故障注入是管理员构造能力，任务、模型和 CLI 不能指定。旧格式与长文本两个发现已修复，子代理独立复跑相关三项（含并发答案）通过。

非阻塞建议：任务状态转移代码仍分散于服务和复用账本，后续生命周期扩展可集中管理，不扩大本票重构。

## Spec

独立子代理对 Issue #11 验收约束无剩余缺口；全部 15 项已独立运行通过。重放结论限于真实 interrupt 恢复及最终服务账本的适配器幂等边界，不声称任意生产节点崩溃后的 exactly-once，也未增加生产自动重试或 SQL 修复。

没有需要代理代替用户签字的人工核验项；未来冻结验收、模型泛化和 UI 阶段仍按后续票独立处理。
