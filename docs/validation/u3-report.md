# U3 历史任务与等待任务恢复

日期：2026-10-19。Issue [#32](https://github.com/ice-ww/MetricGuard/issues/32)，父规格 #29，基线 `4fe472b`。

## 交付与验收对应

| 条件 | 实现和验证 |
| --- | --- |
| 公开列表、稳定身份、目录限定 | GET /api/tasks 只列当前 Web operations 登记任务，返回 ID、问题、快照、状态和窗口；按创建顺序倒序，不导入同目录 CLI 任务或其他目录。公开 HTTP 测试核对只读、鉴权、重启及目录隔离。 |
| 列表打开不执行，等待继续原任务 | 浏览器点击真实任务链接；运行中打开不增加模型调用；回答沿用原 ID，已结束结果重新打开保持相同正文和完整任务状态。 |
| 正常重启保留状态 | 真实 TaskService、HTTP 服务正常关闭再从相同目录开启，完整等待状态相等（含锚点、确认信息、限制和计数）；回答后计数累计。 |
| 空列表和无效 ID | 空工作目录明确显示无任务；无效链接清理旧结果并给出历史选择/新建入口。列表读取失败提示旧列表可能不是最新状态。 |
| 实际持久化流程 | Edge→HTTP→TaskService→SQLite/Docker，完整列表→任务→回答→结果，原先另一条已结束任务记录不变。 |

使用和手动步骤见 [本机界面说明](../local-ui.md)。业务层的日期、预算和澄清规则未修改；本轮不实现 U4 分层证据或 U5 重跑。

## 受控模型与独立参考

受控日期从 2026-01-15 切换至 2026-01-16；首次输入“昨天用户表现怎么样？”，补充“留存”后等待人群问题。正常重启后继续“新增用户”“自然日次日”，实际查询仍为 [2026-01-14, 2026-01-15)，不会重新解释“昨天”。

模型提供方受控，浏览器、持久化与 Docker 查询真实。独立参考直接读取 users 的本地注册日期和 sessions 的活动日期，用 D+1 集合计算分系统人数及留存人数，逐行比对查询证据和日期。另一条新增用户查询保持原记录；查看运行中/结束任务不增加调用。

完整输入、任务 ID、前后状态、参考数值见 [受控记录](u3/controlled.json.gz)。这属于受控跨日自动化验证，**不是人工跨日验收**；本轮未覆盖已有非零工具消耗后进入等待再恢复的情况。
