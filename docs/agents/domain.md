# Domain Docs

## Layout

Single-context: root GLOSSARY.md and docs/adr/.

## Before exploring

Read GLOSSARY.md and ADRs relevant to the area being explored.
If these files do not exist, proceed silently. Domain-modeling
creates them as terminology and decisions become settled.

## Vocabulary

Use glossary terms consistently in issues, proposals, and tests.
Note real vocabulary gaps for domain-modeling.

## Decisions

Explicitly identify any proposal that conflicts with an existing
ADR, and explain why the decision should be reconsidered.
