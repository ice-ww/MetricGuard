# T01 开发数据与参考查询

仅服务 [Issue #2](https://github.com/ice-ww/MetricGuard/issues/2)。这不是 Agent 工具、SQL 安全执行器、统计判定器或冻结任务集。

## 复现

在仓库根目录运行（Python 3.12；依赖以根目录 uv.lock 为准）：

```powershell
uv sync --locked
uv run pytest
uv run mypy
uv run python -m experiments.t01 --output artifacts/t01-new-run --seeds 7 19 41
```

输出目录必须不存在；不覆盖旧实验。自动检查失败退出码为 1；成功为 0，但成功不代表人工验收完成。

每个中性编号 `case-NNN/public/` 仅有 `snapshot.duckdb`。该实例的场景、种子、注入描述和参考结果在同级 `private/`；汇总在根输出目录 `private/report.json`。仅向未来 Agent 挂载单个 public 目录，不能挂载整个仓库或实验根目录。此处只验证材料分离，不宣称提供权限隔离，权限执行属于其他票。

## 固定数据契约

- `users` 的注册时间、系统、版本与渠道固定；`sessions` 独立记录实际运行系统、版本和崩溃。开发实例不模拟观察期升级；手算边界测试故意加入升级验证注册归属仍固定。
- `content_events` 的事件 ID 标识上报，`play_id` 全局标识一次播放。重复上报可有不同事件 ID，但同一播放只有一个 session；重复观看用新 play_id。本实验每个初始会话含两次播放，并保留重复上报。
- `playback_telemetry` 模拟独立进度链路。相同 play_id 的进度取最大观看秒数，时长必须一致且大于零。A3 仅丢弃完成事件，不改变独立遥测。两链路来自相同潜在观看行为，并不意味着统计独立或真实生产遥测已验证。
- `channel_daily.spend_cents` 单位为分。留存用户去重；跨日总体用总留存人数除以总注册人数。成本沿用同一成熟注册日窗口，不能把支出窗口扩到观察日；分母为零返回 null。
- `source_watermarks.complete_before` 为排他完整截止时间，可存在截止时间之后的不完整记录。按 Asia/Shanghai 自然日保守裁剪，D 日用户群要求会话完整到 D+2 零点。查询返回实际窗口和完整性标识；不足实例的本期播放结果为空列表，不伪造零值。
- 基期 `[2026-01-01, 2026-01-08)`，本期 `[2026-01-08, 2026-01-15)`，均为显式用户日期。固定日期不表示已实现“自动选择最近七个成熟日”的产品功能。

## 独立性与适用范围

生成器不写黄金指标。关系 SQL 从业务表计算；另一套 Python 集合/循环独立计算，同样不读取场景 manifest。手算小样例以字面预期锚定午夜跨日、成熟性、固定归属、非等权日汇总、成本窗口和去重，避免只有两套程序相互印证。人工核验仍需用户进行。

A4 另保存基期/本期系统人数与占比、基期结构标准化留存及实际总体留存。SQL 和 Python 分别计算派生量，浮点比较绝对容差为 1e-12；手算例固定标准化 50% 与实际 75%，用于捕获误用本期权重。该参考函数仅用于本实验的完整固定窗口，不适用于缺失系统或不完整窗口。

报告的 `source_hashes` 固定实验代码/SQL；每个 `database_hash` 从 DuckDB 实际读取并排序后计算，重复运行验证逻辑数据相同，不要求数据库文件字节一致。manifest 的 `logical_hash` 则是生成器输入行摘要，两种哈希用途不同。

正常数据包含逐日人数变化和随机留存、崩溃、完成行为。A1 是新版本崩溃关联的留存下降；A2 是一次渠道活动带来的量、质量与成本变化；A3 是完成事件采集丢失；A4 是系统构成变化掩盖 Android 留存下降。后两种带多项参数的业务机制不代表独立随机因果实验。阈值仅用于验证开发实例是否展现预设特征，不是冻结的产品统计判定阈值。不要据此声称因果已证明。

人工记录与实际运行摘要见 `docs/validation/`。未完成人工检查前不关闭 #2，也不把 V4 当成已通过的依赖。
